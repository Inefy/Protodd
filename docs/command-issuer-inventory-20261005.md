# Gameplay command issuer inventory (updated 8 October 2026)

This inventory follows every production UnitCommand call to its acceptance boundary. A proposal, an API-accepted command and a later engine effect are distinct. The owner/priority/budget columns describe current source wiring; they do not certify all of T012–T019's native behavior gates.

## Acceptance boundaries and diagnostic coverage

There are two direct production BWAPI UnitInterface::issueCommand calls: BwapiBridge::issue in src/bwapi/BwapiBridge.cpp and RaceBotModule::issueCommand in src/bwapi/RaceBotModule.cpp. tests/test_command_issuer_inventory.py scans all production .cpp/.hpp inputs and rejects additional direct calls, also rejects BWAPI convenience-order bypasses (excluding reviewed non-BWAPI model/pressure/opening methods), checks the acceptance/error trace at both boundaries, and verifies learned-production dispatch through the bridge. Both boundaries capture the API result and last error. Protodd writes ACTION rows through actionDiagnostic/ProtoddModule::logAction; accepted rows bypass heartbeat suppression, while blocked/rejected rows can coalesce. Per-source ACTION_TOTAL snapshots count every callback and provide independent detailed-row accounting; RaceBot writes COMMAND rows with frame, actor, issuer, command type, target/position, acceptance and error. Reject/pre-API deferral rows do not represent engine acceptance. RaceBot buffers COMMAND rows until a snapshot or onEnd flush; engine fixtures retain earlier native effects and bind exact accepted frame/actor/target/issuer after that flush. Diagnostic exception counters are separate evidence; logging-disabled or failed-output execution is not evidence of complete trace coverage.

beginCommandBudget runs before observe. FrameBudget supplies 96/64/40 UnitCommand API-attempt slots under its current pressure level. defaultUrgentCommandReserve reserves 8/8/5 slots for frame-bus dispatch. Every call reaching BWAPI consumes capacity, including rejected API attempts; a pre-API rejection consumes none. The bus finalizes against commandBudgetRemaining, exposes cutoff winners and deferral age, and rotates tied cutoff urgency fairly. It does not guarantee starvation bounds across unequal urgencies; the native large-army/economy T015 gate remains separate.

The shared envelope contains actor, owner, effective urgency (explicit urgency or compatibility priority), earliest/deadline frames and lease generation. execute(Command) rejects expired/stale envelopes and uses FrameCommandClaims to allow one accepted envelope command per actor/frame. Raw direct issue paths listed above do not all pass that envelope/claim boundary. T012's remaining owner-specific lifecycle/preemption cases stay explicit rather than being assumed covered by the common API sink.
